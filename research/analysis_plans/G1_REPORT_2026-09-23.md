**Execution note — head-row layout correction (transparency, Law #12):** the plan's §2
delegated layout verification to the executor. Verification against the *installed*
transformers 5.17.0 `GPTNeoXAttention` source
(`view(batch,seq,-1,3·dh).transpose(1,2).chunk(3,-1)`) shows the fused QKV weight is
**per-head interleaved at stride 192** — $W_Q^h$ = rows $[192h,192h+64)$,
$W_K^h$ = $[192h+64,192h+128)$, $W_V^h$ = $[192h+128,192h+192)$ — not the blocked
$[Q|K|V]$ layout. The executor implemented the interleaved layout (the dense output
projection is blocked-column per head, as assumed: $W_O^h$ = cols $[64h,64h+64)$).
A blocked-layout implementation would have measured the wrong heads' subspaces; the
script asserts shapes and the layout is recorded in the JSON manifest. The math is
unchanged — only row indices differ — and the plan's verification step worked as
designed. (A second self-caught bug, an SVD unpacking slip, was caught by the script's
own shape path before any number was produced; no results were affected.)
