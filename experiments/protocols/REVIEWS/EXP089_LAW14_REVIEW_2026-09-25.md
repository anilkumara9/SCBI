## Required fixes

### F1 (LOAD-BEARING): pre-register an instrument-health gate — a deaf instrument must yield RUN-INVALID, not KILL
**The flaw:** the scoring instrument — cosine between a decontextualized single-token option embedding and a contextualized final-token premise embedding — is vulnerable to anisotropy collapse (all cosines ≈ 1.0 within float noise), in which case argmax is noise and a ≤37/60 outcome would be recorded as KILL. The §7 KILL row would then license the strong inference "frozen geometry carries no exploitable signal; CLM capability must come from 60M-pair training" from a broken instrument. A KILL must mean *the instrument worked and found nothing*, not *the instrument was deaf*.
**The fix:** add a pre-registered instrument-health guard, e.g.: compute all 120 cosine values; if `max − min < 1e-4` (or equivalently the median |cos(A)−cos(C)| margin is below float-noise), the run is RUN-INVALID (instrument deaf), not a verdict. Report the full margin distribution in the run report regardless.
**Why load-bearing:** without it, the KILL's licensed meaning is ambiguous between "no signal" and "no instrument".

### F2 (LOAD-BEARING): close the §7.1 boundary gap — make the decision tree total
**The flaw:** §7.1 covers (a) aggregate ≥38 with both phrasings >0.5 → CONTINUE, and (b) aggregate ≥38 with opposite tilts → PIVOT. It does not cover aggregate ≥38 with one phrasing at *exactly* 0.5 (15/30) — neither "both >0.5" nor "opposite tilts" fires. The tree must be total before signing.
**The fix:** define the boundary explicitly (recommended: "both tilt toward correct" requires strict >0.5 on both; any aggregate-≥38 outcome failing that — including exact 0.5 — goes to PIVOT, CONTINUE withheld).

### F3: the §7 KILL attribution is [INTERPRETATION], not licensed inference
**The flaw:** the KILL row states unconditionally that "the CLM capability must come from the 60M-pair head training". The test cannot distinguish "needs 60M pairs" from "needs trained heads of any size on Qwen3-8B's different geometry". The strong attribution overclaims what this single instrument can show.
**The fix:** keep the licensed KILL inference minimal — "the free-lunch version dies; the adaptation is shelved pending training resources" — and tag the 60M-pair attribution as [INTERPRETATION] (the §11.5 conditional phrasing is already the right register; conform §7 to it).

### F4: pin eval-mode determinism explicitly
**The flaw:** §6 specifies `device_map="cpu"` and `requires_grad_(False)` but not `model.eval()` / `torch.no_grad()`. HF models load in eval mode by default, but a pre-registration should not rely on a default for determinism (Law #13).
**The fix:** require `model.eval()` and a `torch.no_grad()` context around all extraction, alongside the existing pins.

### F5: state full artifact paths in §4
**The flaw:** §4 lists filenames + hashes but no directory. The artifacts live in `experiments/runs/EXP077_cone_vs_line/` (the code lives in `experiments/runs/exp077/`). An executor porting the wrong directory is a foreseeable failure mode.
**The fix:** give the full relative paths for all four artifacts (and the LOG-331 snapshot path, already present, is correct: `experiments/runs/EXP086_amplifier/weights/pythia-410m/` — directory verified to exist with `model.safetensors` + tokenizer files on 2026-09-25).

### F6: correct the §5 Law #7 wording on lexical overlap
**The flaw:** §5 says the premise-only state text means "option-name token overlap cannot drive the score artifactually". Both option names *do* appear in the premise (once each — verified against the builder: A-first `{A}…{B}. {B}…{C}.`; C-first `{C}…{B}. {B}…{A}.`). The protection is 1:1 balance plus the §7.1 positional diagnostic, not exclusion.
**The fix:** reword to state the balance fact and name the diagnostic as the confound control.
